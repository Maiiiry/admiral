# Release 66 Rocky Linux 10 Multi-Node targeted validation

Audit: `ADM-AUDIT-2026-10-21`<br>
Candidate: Admiral RC5 Release 66, root package-preparation commit `c5365da267eca6f1f5246c60a26c7875f07a5ffa`<br>
Result: **PARTIAL — onboarding and placement scenarios executed; the Rocky Multi-Node cell is incomplete. Overall matrix remains 0/8.**

## Candidate and lab

Three isolated Rocky Linux 10.2 x86_64 guests were cloned from the updated R66 seed `Rocky-10.2-seed-20261023-r66.x86_64.qcow2` (SHA-256 `64d918c2b1b8d69d210372d0e80252798178e3ae9b6b7f4af4dbec2b39b5b3d0`). Each guest had 2 vCPU and 2 GiB RAM; SELinux was enforcing. The hub ran `admirald`, PostgreSQL, Harbor and WireGuard; two workers ran Fleet and rootless Podman. Hub / W1 / W2 WireGuard addresses were `10.99.0.1` / `.2` / `.3`. No production services or customer data were used.

The hub installed all six exact EL10 Admiral RPMs at `0.0.1rc5-66.el10`; the workers completed the supported secure worker installer. Hub recap: `ok=239 changed=105 unreachable=0 failed=0`. W1 and W2 each: `ok=155 changed=54 unreachable=0 failed=0`. Temporary bootstrap credentials were rejected after setup. Rocky's seed used the documented EPEL `python3-pyOpenSSL-25.0.0-1.el10_1` pin; this is a lab dependency exception, not a change to the Admiral RPMs.

The first hub installer attempt failed before package installation because the seed had a root-owned stale `/tmp/admiral-local.repo`, which prevented SCP from replacing it. The helper was corrected in root commit `0221691` to stage at a unique temporary path and install with sudo. Re-run succeeded. The original mode-0600 log is preserved locally with SHA-256 `90b64700d7701657d0d28011bba8267e7b96826efc297cf43779977ede71e9c0`; no product state changed during the failed attempt.

The first placement-harness run exposed a harness-only working-directory issue: after the secure installer set the validator home to mode 0700, rootless Podman could not start from `/home/validator`. The probe was interrupted and its cleanup deprovisioned the workload; the subsequent inventory was empty. The harness now enters `/tmp` before invoking Podman. Its original restricted log SHA-256 is `12a1460dca8e3c7d74e05614e6d6ab3e190a7fda047030e8167826cda1067a4b`.
