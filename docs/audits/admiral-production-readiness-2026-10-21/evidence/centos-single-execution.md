## Limits

This guest did not test public DNS/TLS routing, backup to external object storage, cross-workload network/secret negatives, concurrent update/delete, resource exhaustion, injected systemd/Podman stop or disk failures, or a three-node topology. The first canceled restart confirms only CLI prompt behavior; it is not a lifecycle failure. The audit fixture uses generated credentials only and contains no external secrets.

## Reproduction

The clean installation procedure is `scripts/install-single-node-audit.sh`. Apply the regular workload with `admiralctl apps apply --file examples/apps/e2e-whoami.yaml`. Apply the failed-service fixture with `admiralctl apps apply --file docs/audits/admiral-production-readiness-2026-10-21/fixtures/e2e-failing-db.yaml`, then provision with the command recorded in issue #227. Compare `admiralctl operations show`, `admiralctl instances list`, rootless `podman pod ps`, `podman ps --all`, and the per-instance user systemd units. The non-secret fixture and hashes are tracked; raw logs remain local and mode `0600`.
