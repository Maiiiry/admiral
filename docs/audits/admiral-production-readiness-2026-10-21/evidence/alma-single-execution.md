## Limits and observations

The first install wrapper returned 127 even though the install script printed completion and Ansible reported no failed tasks; a repeated install returned 0. The first-run status discrepancy remains unexplained. The app definition had no hostname configured; `admiralctl routes list` was empty, so public Internet ingress, DNS and TLS routing were not exercised. The `e2e-whoami` tier disables manual backups by default; the first backup request was correctly rejected with HTTP 403. The dedicated backup fixture explicitly enables the tested policy. The first attempt to connect to PostgreSQL as the default role `postgres` failed because Admiral generated a different user; the test was corrected to use the container's configured credentials without printing them.

The post-reboot observation is eventual recovery, not proof of zero divergence. Node heartbeats showed two active pods and both instance records converged to `running/healthy`; the transient window and exact timestamps are retained above. Memory-pressure, disk-full, host filesystem fault, control-plane/database outage, network partition, multi-node scheduling and concurrent same-instance update/delete scenarios are not covered by this guest run.
