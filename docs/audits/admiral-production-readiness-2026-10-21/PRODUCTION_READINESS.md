## What would change this decision

The requested matrix is Fedora Rawhide, Rocky Linux 10, AlmaLinux 10 and CentOS Stream 10 on x86_64 in both topologies (eight cells). Prior RC subsets and scoped Single-Node executions do not complete the audit; CentOS Stream Multi-Node now has real runtime evidence for install, placement and cleanup, but still needs the remaining lifecycle, recovery, security, concurrency and performance scenarios. Multi-Node cannot become READY until `ADM-F-003`, `ADM-F-005`, `ADM-F-006` and `ADM-F-007` are fixed and revalidated. Before either topology can be READY, `ADM-F-001` and `ADM-F-002` must also be fixed or accepted with bounded safe behavior, and high-impact isolation, integrity, recovery and false-completion scenarios need reproducible evidence. Performance measurements must include sample counts and percentiles, without inventing SLOs. Any candidate code correction requires a new six-RPM Release increment, a new immutable candidate, and revalidation of affected cells (all six Release fields increment for any RPM rebuild).

## Current answer to the audit question

Available evidence shows real Single-Node lifecycle and three-node hub-and-spoke operation, including worker loss/rejoin, reboot, controlled packet partition and hub restart. Findings include three MEDIUM and four HIGH issues from runtime probes and source/config audit: replay can create another instance; instance health remains last-known healthy while its worker is offline; Harbor emits an unsafe Markdown URL on Rocky and Fedora; the Go 1.26.7 HTTP/2 listener is vulnerable and reachable; Rocky, Fedora and CentOS Stream hubs lose runtime WireGuard peers on startup until manual reconstruction; production config accepts shipped placeholder values for the secrets and callback keys; and CentOS Stream Single-Node and Multi-Node probes reported success/healthy state with a failed required database service. The config-parser behavior was executed as a focused test; full process exploitation was not attempted. Single-Node and Multi-Node are **NOT READY** until the HIGH findings affecting each topology are fixed and revalidated. Concurrent behavior, other security negatives, resource exhaustion, latency, database recovery, performance and full matrix evidence remain open.
